# Madoyomi app (Tauri 2 + Vue 3)

Desktop shell and UI. See [../docs/PLAN.md](../docs/PLAN.md) for the architecture and [../docs/phases/](../docs/phases/) for the phases: the screens are [Phase 3](../docs/phases/phase-3-frontend-mvp.md)'s, playback [Phase 4](../docs/phases/phase-4-playback.md)'s, and the manga reader [Phase 5](../docs/phases/phase-5-manga-reader.md)'s (in progress: the paged mode).

```powershell
pnpm install
pnpm tauri dev      # run the desktop app (Vite + Rust shell); starts the backend jar
pnpm dev            # UI only, in a browser at http://localhost:1420
pnpm test           # Vitest
pnpm lint           # ESLint
pnpm format         # Prettier
pnpm typecheck      # vue-tsc
pnpm tauri build    # NSIS/MSI installer
cd src-tauri; cargo test; cargo clippy --all-targets   # Rust shell tests and lints
```

    - `realtime.ts`: the vue-query defaults and the app-wide event subscriptions (extension installs, repo refreshes, and since Phase 4 `playbackEvents`: every event goes into the `playback` store, from which the playing row's progress is drawn live; WATCHED marks the episode in the cached list at once, CLOSED writes its last position there, and both refetch the anime's episodes; a reconnect forgets the session it followed).

`usePlayEpisode`: `playEpisode` with a start position, remembering the choice for the source; `noVideoError`), `useNextEpisode` (the next-episode flow of a details page: the toast's countdown, auto-play with the remembered choice, else the preference's, and no picker, and what stops it), `usePlayerSettings` (the backend's player settings: `usePlayerSettings`, `useWatchedThreshold` for the resume prompt, `usePlayerLanguages`, and `useSetPlayerSettings`, shown at once and rolled back on an error), `useReaderSettings` (Phase 5: the backend's reader settings, `useReaderSettings` and `useSetReaderSettings`, the page cache's cap, shown at once and rolled back on an error; `usePageCache`, read each time Settings opens and after a change; `useClearPageCache`; `formatBytes` and `formatLimit`), and for the reader (Phase 5 Stage 2): `useUpdateChapters`/`useUpdateChapter` (read marks and progress, written into the cached chapter list), `usePageLoader` (the reader's pages as blobs, at most 4 requests, the page shown first, −1/+4 around it, aborted and revoked outside that window, `retry` and `retryTransient`), `useReadingProgress` (the page saved debounced, the read mark on the last page, flushes on leaving, retries), `useFullscreen` (the window's, through Tauri)) and the query keys (`chapterPages`).

## Routes

| Route                               | View                                   | Status                                                                                                                                                                                                                                                                        |
| ----------------------------------- | -------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `/` → `/library`                    | `LibraryView`                          | done (Stage 5): the saved entries of the current kind, sorted by date added or title, empty state to Browse                                                                                                                                                                   |
| `/browse`                           | `BrowseView`                           | done (Stage 4): by language, pins, built-in Local, unusable ones point to Extensions                                                                                                                                                                                          |
| `/browse/:sourceId`                 | `SourceView`                           | done (Stage 4): Popular/Latest/Search, filter sheet, endless grid                                                                                                                                                                                                             |
| `/anime/:id`, `/manga/:id`          | `AnimeDetailsView`, `MangaDetailsView` | done (Stage 5): details, refresh, library, the episode/chapter list (or seasons); they set the anime/manga switch. Phase 4: Play through the video picker, resume, progress, watched marks. Phase 5: chapters open the reader, Start/Continue reading, read marks             |
| `/manga/:id/read/:chapterId?page=N` | `ReaderView`                           | Phase 5 Stage 2: the paged reader without the shell (right to left by default), progress saved and resumed, chapter to chapter, fullscreen                                                                                                                                    |
| `/extensions`                       | `ExtensionsView`                       | done (Stage 3): tabs, filters, install/update/uninstall, trust                                                                                                                                                                                                                |
| `/repos`                            | `ReposView`                            | done (Stage 3): add (type detected), remove, refresh, events                                                                                                                                                                                                                  |
| `/downloads`                        | `DownloadsView`                        | placeholder (Phase 6)                                                                                                                                                                                                                                                         |
| `/settings`                         | `SettingsView`                         | done (Stage 6): theme, language, the backend's version, folders and logs, the kind's sources with settings. Phase 4 Stage 5: Player (auto-play, the watched threshold, quality, server, languages, mpv). Phase 5 Stage 1: Reader (the page cache's cap, what it holds, Clear) |
| `/settings/source/:id`              | `SourceSettingsView`                   | done (Stage 6): the source's preferences (`PreferenceRenderer`), saved as they change; unusable ones to Extensions                                                                                                                                                            |
| anything else                       | `NotFoundView`                         |                                                                                                                                                                                                                                                                               |

The routes of one kind (`/browse/:sourceId`, `/anime/:id`, `/manga/:id`, `/settings/source/:id`) go back to their section's list when the switch changes kind. A details page (`meta.navFromPrevious`) belongs to the section it was opened from: the sidebar keeps marking Browse or Library, and a kind change goes back to that list. Opened directly, it marks Library.

## Live check of the API operations

`src/api/__tests__/operations.live.spec.ts` runs only when `MADOYOMI_LIVE_URL` and `MADOYOMI_LIVE_TOKEN` point at a running server, e.g. one from `../tools/run-server.ps1`:

```powershell
$env:MADOYOMI_LIVE_URL = 'http://127.0.0.1:<port>'; $env:MADOYOMI_LIVE_TOKEN = '<its token>'
pnpm vitest run src/api/__tests__/operations.live.spec.ts
```

It validates every document in `src/api/operations/` against the server's schema, checks that a wrong token gets 401, checks that adding yuzono as a manga repo is refused with `REPO_TYPE_MISMATCH` and the packages (what the Repos screen's type detection relies on; it fetches the index and writes nothing), receives `extensionStoreRefreshed` through `ws.ts` after a repo refresh (that needs at least one repo), and runs a filtered search on an installed source of each kind: one filter changed through `filterChanges`, which must find entries (it needs the source's site; a source whose site fails is recorded and the next one tried, and a kind with no installed source is skipped). It also refreshes the first Popular entry of one source per kind the way the details page does, and puts it into the library and out again (an entry that was already there is put back). It changes one preference (a switch, checkbox or list) of a configurable source of each kind the way the settings page does, reads it back and restores it. Last (Phase 5), it reads a manga chapter's pages through the backend (MangaPill when installed): the first page from the source, then from the cache (and through `fetchAsset`, the token in the header), a prefetch of the next three until they are cached, and a page past the end as `NOT_FOUND`; then it saves the chapter's page, one past the end (clamped) and the read mark through `updateChapter(s)`, and puts the chapter back. Run it after changing an operation or a type.

## Backend sidecar

`pnpm tauri dev` starts the newest `../server/api/build/Madoyomi-Server-*.jar`, so build it once with `.\gradlew.bat :api:shadowJar` in `server/`. The shell (`src-tauri/src/sidecar.rs`):

- runs `java -jar <jar> --data-dir <dir>` with a per-session random `MADOYOMI_TOKEN`, and keeps the backend's stdin open (the backend exits when it closes);
- waits for `MADOYOMI_PORT=<port>` as long as the JVM lives (up to 5 min), then for `GET /health`, and checks `/health` every 5 s after that;
- restarts the backend after an exit or a hang, after 1, 2, 4 and 8 s, and gives up after 5 failed starts in a row (Retry in the UI);
- resolves java and the jar again for every start: a missing jar fails at once, with no restarts, and Retry looks for it again (so does a restart in a debug build, which then runs a jar rebuilt since);
- writes the backend's output and its own lifecycle lines to `<data dir>/logs/sidecar.log`.

Environment overrides: `MADOYOMI_SIDECAR_JAR` (jar), `MADOYOMI_JAVA` (`java.exe`; default `../tools/bin/jdk-21`), `MADOYOMI_DATA_DIR` (default `%APPDATA%\Madoyomi`).

mpv (Phase 4) is run by the backend, not the shell. Settings → Player can name the `mpv.exe` (Stage 5); it comes first. Otherwise the shell tells the backend where it is: `MADOYOMI_MPV` is passed on if set, else set to `../tools/bin/mpv/mpv.exe` when that exists (release: `resources/mpv/mpv.exe`), else left out, and the backend uses `mpv.exe` from PATH. `MADOYOMI_PLAYER_DIR` (mpv's config dir) is passed on if set, else set to `../player` (release: `resources/player`). `sidecar.log` has a `player:` line with both. mpv is the JVM's child, so it is in the same Job Object and dies with the app.

The UI talks to it through:

| Command or event       | What it does                                                                                                                                                                                                         |
| ---------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `get_backend_status`   | Status snapshot: `state` (`starting`, `healthy`, `restarting`, `failed`, `stopped`), `attempt`, `elapsedMs`, `slow`, `baseUrl`, `pid`, `serverVersion`, `error`, `exitCode`, `retryInMs`, `dataDir`, `logDir`, `seq` |
| `backend-status` event | The same snapshot, on every change and once a second while starting                                                                                                                                                  |
| `get_backend_info`     | `{ baseUrl, token }` once healthy (waits while starting; the port changes after a restart, the token doesn't)                                                                                                        |
| `restart_backend`      | Retry after `failed`, or skip the backoff                                                                                                                                                                            |
| `open_backend_logs`    | Show `sidecar.log` in Explorer                                                                                                                                                                                       |

`src/stores/backend.ts` wraps these, and `src/components/BackendGate.vue` shows the splash, the failure screen and the restart overlay.

In plain `pnpm dev` there is no shell. Put `VITE_MADOYOMI_URL` and `VITE_MADOYOMI_TOKEN` of a server started with `../tools/run-server.ps1` into `.env.local` (gitignored) to use it from the browser.
